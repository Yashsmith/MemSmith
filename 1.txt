2. Agent loop: take inspiration from Pi

I would make Pi's runtime architecture your starting point.

Pi's extension system exposes lifecycle events and runtime context, while its session manager and compaction system are reasonably cleanly separated. 

Your agent loop should conceptually be:

while agent.running:

    context = context_manager.build(agent)

    response = model.generate(context)

    if response.tool_call:
        result = tool_executor.execute(response.tool_call)

        event_bus.emit(
            ToolExecuted(...)
        )

    elif response.subagent_call:
        result = subagent_manager.spawn(...)

    else:
        agent.finish_turn()

Then expose hooks:

before_turn
after_turn

before_model_call
after_model_call

before_tool_call
after_tool_call

before_subagent_spawn
after_subagent_complete

before_compaction
after_compaction

before_skill_change
after_skill_change

before_meeting
after_meeting

before_artifact_write
after_artifact_write

This is where Pi is particularly useful.

Your Scrum engine can then sit above the agent runtime and subscribe to those events.
